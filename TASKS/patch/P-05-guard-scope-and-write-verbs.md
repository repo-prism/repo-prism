# P-05: 只读扫描器补「调用门槛」与「写动词黑名单」

**状态**：已完成（2026-10-09）
**卡号说明**：本卡不在 001–020 的产品血统内，属工程补丁，故编入 patch 序列（见 [README](README.md)）。

## 目标

修掉 `scripts/read-only-guard.sh` 的**误报**，同时把**漏报面**补回来。

## 上下文：P-02 留下的两个真实缺陷

加 TASK-010 的分析模块时，扫描器一次性报出 55 条违规，其中 53 条是误报。

### 缺陷一：规则 1 没有「这条语句在不在调 Git」的门槛

P-02 的实现按 `;` 切语句后，**无条件**校验语句里所有纯小写词字面量。
于是任何普通语句都会被审：

| 被误报的字面量 | 来源 | 实际是什么 |
|---------------|------|-----------|
| `public-api` / `mass-deletion` / `test-deleted` … | 规则表 id | 字符串常量 |
| `rs` / `ts` / `py` / `go` / `java` | 扩展名匹配 | 字符串常量 |
| `conflict` / `staged` / `unstaged` | 分组标识 | 字符串常量 |

`AGENTS.md` 的只读宪法管的是**核心层调用了哪些 Git 命令**，
没在调 Git 的语句里出现小写词毫无风险 —— 规则 1 的门槛过宽。

（同一类误报 2026-10-09 上午也发生过一次：违规 token 其实在**注释**里。
P-02 的「已知边界 2」记的是那个；本卡记的是更根本的那一层。）

### 缺陷二：门槛一加，`let args = ["push"]` 这类写法就漏了

修缺陷一的直接做法是「只审含 `Command::new("git")` 或 `self.run(` 的语句」。
但这样一来，把命令与调用**分开写**的形状会掉出网外：

```rust
let args = ["push", "-u", "origin"];
self.run(&args)?;          // ← 违规发生在这条语句，字面量却在另一条
```

两条语句是独立切分的，前一条没有 Git 调用标记，规则 1 不会再看见它。

### 顺带补的第三个洞

`DANGER_RE` 里**没有** `--textconv` / `--filters`。这两个选项本身不是写操作，
但会让 Git 执行仓库自定义的转换器 —— 正是 `SECURITY.md` 威胁 1 要防的事，
而 P-02 只把「不传 `--textconv`」写进了卡片，没写进扫描器。

## 实现：四层校验

| 层 | 规则 | 生效范围 |
|----|------|---------|
| 0 | **门槛**：语句须含 `Command::new("git")` 或 `self.run(` | 决定 1/2/3 层是否运行 |
| 1 | 语句内纯小写词必须是已知只读子命令（或 `list`）；**动词之后的小写词按参数处理** | 仅 Git 调用语句 |
| 2 | `-x` / `--xxx` 不得命中危险选项表（新增 `--textconv` / `--filters`） | 仅 Git 调用语句 |
| 3 | 条件动词必须带明确只读标志 | 仅 Git 调用语句 |
| 4 | **写动词黑名单**（`push` / `commit` / `fetch` / `pull` / `rebase` / `reset` / …） | **任何语句** |

第 4 层是第 0 层门槛的配套：它是全局的，不要求本语句在调 Git，
正好兜住「命令与调用分开写」。两层一收一放，误报消失、漏报面比 P-02 之前更宽。

### 为什么要区分「动词之后的小写词」

`git remote get-url origin` 里 `get-url` 与 `origin` 都是纯小写词，
但它们是**参数**而不是子命令。P-02 的实现会两者都报。
现在只校验动词位置及之前的小写词，动词之后的交给第 3 层
（`remote` 是条件动词，缺读标志就报）与第 4 层（写动词）兜。

### 规则 3 的报错信息也改了

只报「条件动词 `worktree` 缺少明确的只读标志」，看不出是 `worktree list` 还是
`worktree remove`。现在会把动词之后第一个非选项 token 一并报出来
（`（疑似写子命令 remove）`）。

### 一个实现坑（已写进脚本注释）

门槛的判据**不能**用 `-v git_call_re=...` 注入：awk 会处理 `-v` 值里的反斜杠转义，
`\(` 被吃掉后正则变成 `Command::new("git")` —— 那是「`Command::new` 后跟一个分组」，
永远匹配不上，而且**静默失效**。改用 awk 正则字面量写在程序里。

## 自认的代价（已写进脚本注释）

- 第 4 层对**任何**语句生效，因此面向用户的提示文案里若出现被引号包起来的写动词
  （如 `"push 被禁止"`）也会被拦。宁可让人改一句文案，也不放过一处写操作。
- 第 4 层仍是静态字面量分析，不做数据流追踪：`["pu","sh"].concat()` 之类依旧绕过。
  这是「已知边界」，真正的兜底是人工审查。

## 与 P-02 的关系

并补了两个选项。P-02 卡片本身不改 —— 它记录的是当时的事实。
