# TASKS/patch —— 工程补丁序列

本目录存放**不属于产品血统**的工程补丁卡。

`TASKS/001-0xx` 这一串编号是**产品血统**，由原规划 `RepoPrism-仓库棱镜-001`…`006`
一次性排定（001–016 已排到 v0.2，017–020 属 v0.3）。产品能力的增减只能改这条血统。

工程补丁（安全加固、依赖卫生、文档漂移这类「不新增产品能力但必须做」的事）
走 `P-0N` 系列，两者编号互不占用。

## 为什么要有这条规则

2026-10-09 出过一次真实的编号事故：一轮自发的工程整改把补丁卡编成了
`TASK-008`…`TASK-011`，而血统里 008 = CLI 规范化 + Skill 打包、009 = MCP Server、
010 = 变更分析、011 = 外部集成——四个号全被占掉。后果是「TASK-008 是什么」
在文档里有了两个互不相容的答案。
