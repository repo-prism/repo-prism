## 问题与处置

### 问题 A：`SPEC.md` 被截断，且未覆盖已实现的功能

原文 42 行，结尾停在 `repoprism skill --path`——**代码块未闭合**，US-4 未写完，
US-5 及之后不存在；已实现的 `commits()` 与提交图在 SPEC 里没有对应条目。

**处置**：重写为 v0.2。

- 闭合所有代码块
- 新增 US-5（提交图）、US-6（Agent 出口）、US-7（编排集成）
- 新增**数据模型**章节（此前 CLI 集成测试注释写着「schema 与 SPEC.md 数据模型一致」，
  而 SPEC 里根本没有数据模型）
- 新增**非功能要求**章节（只读安全 / 性能 / 跨平台）
- 每条能力打 `[已实现]` / `[待实现]` 标记，并给出末尾的状态对照表

### 问题 B：`SECURITY.md` 教的 CI 扫描方法已失效

原文要求 CI 用：

```bash
grep -rn 'Command::new("git")' crates/repo-prism-core/src/ \
  | grep -oE 'arg\("[a-z-]+"\)'
```

而 `scripts/read-only-guard.sh` 的注释已论证这条路**扫描结果恒为空**：
Rust 链式调用把 `.arg()` 写在后续行，只匹配单行的 grep 抓不到跨行的写命令，
还会把 `--show-toplevel` 这类合法选项误判为子命令。

**处置**：扫描章节改为引用脚本，并**删除重复的 `ALLOWED` 名单**
——名单重复过一次，就与实现漂移了一次。现在脚本是白名单的唯一事实来源。

同时更新威胁模型，把已经落实的应对写实：

- 威胁 1（textconv）→ 已由 `--no-textconv` 落实
- 威胁 2（LFS）→ 已由「二进制只标记不读内容」落实
- 威胁 3（diff 注入 UI）→ 已由「纯文本节点渲染」落实
- 威胁 6（病理仓库资源耗尽）→ 新增，对应 5000 行上限与显式截断

「历史教训」一节**保留**：这段教训有留存价值，删掉只会让后人重犯。

### 问题 C：README 宣传了未实现的能力

原文列出「文本化仓库 / 架构图 / AI 文档 / Agent 协同（CLI / Skill / MCP）」，
以及 `repoprism open . --view changes`、`repoprism skill --path`，都当作已提供。

**处置**：已实现的标 ✅，未实现的标「计划中」，并指向 `SPEC.md` 作为状态事实来源；
新增「开发」「文档地图」两节。
