# P-08: 本地模型的出网边界 —— 代理不得改道，字段名要有权威依据

**状态**：已完成（2026-10-09）
**卡号说明**：本卡不在 001–020 的产品血统内，不新增产品能力，属工程补丁，
故编入 patch 序列（见 [README](README.md)）。

## 起因

P-07 把 `summarizer.rs` 的两处 `ureq` 调用变成了「真的跑过」，但它自己在文件头写清了
两处**做不到**的事：

> **本文件不替代真实模型验证**：stub 只能证明「我们这一侧写得对」，
> 证明不了「真实 Ollama 的响应形状与我们的假设一致」。

本机装不了 Ollama，于是这条缺口只能从另外两个方向逼近 —— 而这两个方向都不需要模型。

## 一、代理改道：一条连文档都没写过的隐含假设

`summarizer.rs` 的安全承诺是一句话：**唯一出网点是到 127.0.0.1**。
`validate_endpoint()` 把 host 卡死在 `localhost / 127.0.0.1 / ::1`，
于是「不把仓库发到外部」看起来成立。

**但 `ureq::get()` / `ureq::post()` 构造的是默认 agent，而 `HTTP_PROXY` /
`HTTPS_PROXY` / `ALL_PROXY` 这类环境变量是会改写连接目标的。**
若默认 agent 遵循它们，endpoint 上写着的 `127.0.0.1` 就不再是真正要连的地址——
**校验层看着是绿的，连接目标却由环境变量说了算。**

这不是假想场景：本仓库的开发机上 `HTTP_PROXY=http://127.0.0.1:58883` 就是设着的
（企业网、CI、容器里是常态）。而 `read-only-guard.sh` 是 Git 动词白名单、
**看不见 HTTP 调用**，这条边界没有任何静态扫描兜底。

**实测结论：ureq 2.12.1 的默认 agent 不改道回环请求**，承诺站得住。
但「站得住」与「被验证过」是两件事，所以本卡把它钉成了断言。

## 二、字段名：把响应形状的来源从「我们」换成「厂商」

P-07 的 stub 响应体是**我们自己写的**。如果 `response` 被打成 `message`，
我们大概率也会照着同一个错误去写 stub —— 两边一起错，测试照样绿。

本卡引入 `summarizer_contract.rs`：响应体**逐字取自** Ollama 官方
`docs/api.md` 的示例（该仓库公开可读）。字段名从此由**被对接方**定义。

### egress 用例为什么能失败

光「设个代理变量然后断言成功」是**测不出东西的**：客户端不认代理时它绿，
认代理但代理恰好能通时它也绿。所以测试先做两件事：

1. **确认那个代理地址是死的** —— 先 `connect_timeout` 一次，必须连不上。
   于是「用了代理」必然导致调用失败，绿与红被彻底分开；
2. **清掉 `NO_PROXY`** —— 否则「走直连」可能只是被它豁免，而不是客户端真的不认代理。

再断言 stub 收到的请求行是 **origin-form**（`/api/tags`）而不是代理用的
**absolute-form**（`http://host/api/tags`）。

**本用例只断言性质，不断言机制**：究竟是不读代理变量、还是读但豁免回环，
本测试不做区分 —— 两者对这条安全承诺等价。

### 契约用例里的反向用例

`a_renamed_response_field_is_not_silently_accepted` 是刻意的：
没有它，`generate_reads_the_vendor_published_...` 只能证明
「我们的解析器能读出我们自己写的东西」，等于退回 P-07 的盲区。

## 为什么没有改用公网模型端点

本机装不了 Ollama 时，一个看似可行的办法是找一个公开可用的模型服务来「真跑一次」。
**不做**，理由三条：

1. 需要**放宽 `validate_endpoint` 的回环限制** —— 那正是本卡要加固的第 4 层缓解，
   为了验证它而先把它拆掉，方向相反；
2. 会把**真实的仓库内容**（相对路径、规则结果）送到一个未经审核的第三方；
3. 公网上暴露的模型服务多属误配置，使用它们本身也不合适。

官方文档是公开资源，公网服务不是。**本卡只用前者。**

## 教训

1. **「回环地址」是一个地址，不是一个保证。** 中间任何一层都可能改写连接目标
   （代理、DNS、hosts、容器网络）。写下「只发到 127.0.0.1」时，
   要问的是「这个地址**真的被用到了**吗」，而不是「变量里写的是不是 127.0.0.1」。
2. **安全要求不要藏在库的默认值里。** 原来写 `ureq::get(&url)`，
   读代码的人无法判断作者有没有考虑过代理。显式构造 agent 的运行时行为一模一样，
   但它让下一个人**看得见**这里做过判断。
3. **测试的输入来源决定了它的证明力。** 自编的 stub 响应证明「代码自洽」，
   厂商文档的示例证明「与外界一致」。前者便宜、后者贵一点，但**两者不可互相替代**。
4. **不能失败的前提断言等于没有前提。** egress 用例先确认代理是死的，
   这一步不是装饰 —— 没有它，整个用例在「客户端认代理且代理能通」时也会绿。
